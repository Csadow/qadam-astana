# Privacy, reliability and user safety

Precise geolocation is requested only after a user click and browser permission. It lives in page memory; a clear-location action removes it. Group interests, route edits, up to ten undo snapshots, mission checkmarks and a bounded generation cache are also page-memory-only. Origin-dependent graph snaps, shortest-path trees and route geometry are bounded page-memory caches; clearing a custom location clears the router caches. Deadlines, reserve choices, recovery history and selected story remain in page memory. The app writes no location history, cookies, account database, localStorage, sessionStorage or analytics events. Preset landmarks are available without location permission.

Recommendation ranking and route planning run locally in the browser. Map geometry is included with the app; the browser makes no external map-tile requests. The optional generation request sends only selected public POI IDs, estimated visit lengths, language, mood, category interests, up to five anonymous group preferences weather, indoor/outdoor intent, excluded interest categories, bounded time budget and three booleans (family, quiet, sockets). The server reconstructs trusted records and sends those public records to Gemini. It never forwards the user's precise origin or raw query. Hosting infrastructure and the model provider may still process network metadata. Opening a source link is an explicit external navigation.

POI records are untrusted input. Text is escaped before rendering; map source links are restricted to canonical OSM record URLs. The model is told not to follow source instructions, and its output must contain one bounded explanation, activity and mission per selected POI, with valid citation IDs belonging to that place. Exterior-only stops cannot cite interior exhibits. Fabricated IDs, unsupported citations, duplicate records, malformed JSON, common unsupported operational claims, HTTP errors and timeouts trigger the labelled fallback. Citation validation does not prove semantic support for every generated claim; generated prose remains visibly labelled and source facts are shown separately. Venue names, coordinates, hours and accessibility come from source records, never the model.

Unknown opening hours are not “open now.” The parser handles a limited weekly subset and treats unsupported expressions as unknown. Availability is not guaranteed even when a visit fits the published schedule. Accessibility tags are not verified step-free routes. Sockets, quietness, night security and lighting remain unknown without evidence. Official descriptions support some museum interactive exhibits, but current availability is still unverified. Activity suggestions are separately labelled.

Local serving is loopback-only. API responses are no-store; bodies are limited to 8 KiB; cross-origin browser writes are rejected. The public judge Site has paid generation disabled. A future public live-model service would need authentication/rate limits and budget controls. Keep `.env` ignored and configure hosted secrets through the hosting provider, never client JavaScript.

Future monetization must not bypass relevance or feasibility filters. Sponsored results must be clearly labelled. Location histories are not part of the business model.

The public judge preview sets `QADAM_PUBLIC_DEMO=true`, returns a labelled retrieval/template response before any provider request, and has no hosted Gemini key. Live generation remains opt-in in a local installation with its own server-side key. Neither public-demo status nor provider keys can be changed through request bodies.

## Adaptive companion

Confirmed stop positions, finished/unavailable place IDs, the original return point, fixed deadline, manual weather reports and up to 20 rehearsal undo states remain in page memory. No location watcher or background timer is started. Ending the companion clears its session and restores the original plan; reloading clears walk progress. Actual time is refreshed on user actions and rounded up to the next minute. Rehearsal advances explicitly simulated travel/visit/delay time and can undo it; actual mode cannot rewind time.

The generation boundary is unchanged: only the selected remaining public places and existing normalized context are sent. Session history, event types, current/return coordinates, exact clock and deadline are not sent. Selected place IDs can still reveal a coarse area of interest. An unavailable-place report excludes that place only from this walk and is not published as a source fact. Routes, deadlines and reserve are estimates, not arrival guarantees. If no further visit fits, only the return is shown; missing connectivity, lateness or a walking-cap conflict is disclosed.
